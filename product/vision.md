# Product Vision

- Status: Draft
- Updated: 2026-08-24

## Vision

現場の業務知識を、利用者が理解・変更・改善できる「動くモデル」にする。

## Problem hypothesis

多くの現場では、業務知識がExcel、チャット、口頭説明、個別システムに分散している。その結果、次の問題が起きる。

- 同じ情報を複数箇所へ転記する
- 業務ルールが担当者の頭の中にしかない
- 例外処理が増えるほどシステムと実務が乖離する
- 小さな業務変更にも、開発者への依頼や長い待ち時間が必要になる
- 現在の業務がなぜその形なのか説明できない

## Target users hypothesis

最初の対象は、専任の開発チームを持たず、表計算と複数SaaSを組み合わせて業務を運用している小規模チームとする。

ただし、対象業務はまだ決めない。販売管理、問い合わせ管理、契約管理などの候補から、具体的な利用者と業務シナリオを調査して選ぶ。

## Value proposition hypothesis

利用者は、業務上の「もの」とその関係、状態、権限、処理を定義することで、個別開発より速く、表計算より安全に、自分たちの業務システムを改善できる。

## Product principles

1. **業務を先に、画面を後に** — UIの都合からではなく、現場の概念と流れから設計する。
2. **柔軟性には説明可能性を伴わせる** — 自動処理が、なぜ実行されたかを追跡できるようにする。
3. **安全な変更を標準にする** — 下書き、検証、公開、履歴、ロールバックを設計に含める。
4. **段階的に理解できる** — 初心者には単純に、必要な人には深く扱える構造にする。
5. **出口を塞がない** — データの入出力とAPIを重視し、利用者を閉じ込めない。

## Non-goals for the first release

- あらゆる業種を最初からカバーすること
- 完全なERPを構築すること
- コードを書ける人向けの開発基盤を主対象にすること
- AIに業務判断を全面的に委ねること
