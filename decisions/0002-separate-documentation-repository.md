# ADR 0002: Manage durable documentation in a separate repository

- Status: Accepted
- Date: 2026-08-24

## Context

Ordoでは、プロダクト探索、ドメイン知識、アーキテクチャ判断、学習記録そのものを独立した成果として育てたい。アプリケーションコードと同じリポジトリに置くと、実装の構成やリリースサイクルに文書の整理方法が引っ張られる。

一方、リポジトリを分けると、仕様変更と実装変更の対応関係が見えにくくなる可能性がある。

## Decision

長期的に維持するドキュメントの正本を `ordo-docs` で管理する。

`ordo-docs` の対象は、プロダクト、ドメイン、アーキテクチャ、ADR、学習記録とする。`ordo` には、アプリケーションコードと、セットアップ手順など実装に直接付随する説明を置く。

リポジトリをまたぐ関連変更では、文書から実装のIssueまたはコミットを参照し、実装側からも対応する文書を参照する。

## Alternatives considered

- すべてを `ordo` の `docs/` で管理する: コードとの同期は容易だが、ドキュメントを独立した学習・設計資産として扱いにくい。
- Wikiや外部ノートサービスで管理する: 編集は容易だが、Gitによるレビュー、履歴、ローカル検索、自動検査との一貫性が弱くなる。

## Consequences

- 実装前の探索やドメイン研究を、コード構成から独立して進められる。
- ドキュメント専用の検査、公開方法、変更フローを設計できる。
- 変更が二つのリポジトリにまたがるため、相互リンクと同期を意識する必要がある。
