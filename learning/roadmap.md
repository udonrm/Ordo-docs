# Learning Roadmap

- Status: Draft
- Updated: 2026-08-24

このロードマップは機能一覧ではなく、プロダクトを作る過程で身につけたい能力を整理したものです。各フェーズで、文書と動くソフトウェアの両方を成果として残します。

## Phase 0: Problem Discovery

**問い:** 誰のどの業務課題を解くのか。

- 業務ヒアリングと現状業務フローの可視化
- 用語集、アクター、課題、制約の整理
- 競合・代替手段の分析
- プロダクトビジョンと仮説の更新

成果: Problem Statement、As-Is業務フロー、用語集

## Phase 1: Product Definition

**問い:** 何を作れば価値を検証できるのか。

- PRDと成功指標
- ユースケース、ユーザーストーリー、受け入れ条件
- To-Be業務フロー
- Event Stormingとドメイン境界の検討

成果: PRD、ドメインモデル、最初の縦切りシナリオ

> FDE（Forward Deployed Engineer）は文書の種類ではなく、顧客の現場に深く入り、課題発見から実装・定着までをつなぐ役割・働き方。Ordoでは、実在または具体的に想定した利用者との短いフィードバックループとして実践する。

## Phase 2: Walking Skeleton

**問い:** 最小構成で、価値の流れを最後まで通せるか。

- LaravelとPHPの実行基盤
- 認証、組織、権限の最小構成
- CI、静的解析、テスト、コードスタイル
- 最初のエンティティ定義からレコード操作まで

成果: デプロイ可能な最小アプリ、アーキテクチャ概要、品質ゲート

## Phase 3: Meta-model

**問い:** 異なる業務を共通の概念でどこまで表せるか。

- エンティティ、フィールド、リレーション、制約
- ビュー、フォーム、検索、集計
- スキーマ変更とデータ移行
- マルチテナンシー、認可、監査ログ

成果: メタモデルの実装と、その限界を示す複数の業務例

## Phase 4: Workflow and Automation

**問い:** 業務の状態変化とルールを、安全かつ説明可能に実行できるか。

- 状態遷移、承認、通知
- 条件とアクション
- 冪等性、非同期処理、失敗時の回復
- 実行履歴とデバッグ体験

成果: ワークフローエンジン、自動処理の観測・再実行機能

## Phase 5: Product Experience

**問い:** 複雑な機能を、利用者が段階的に理解できるか。

- 情報設計とインタラクション設計
- デザイントークンとコンポーネント設計
- アクセシビリティとレスポンシブ対応
- 空状態、エラー、オンボーディング

成果: 小さなデザインシステム、利用テストの記録

## 継続する学習ループ

各変更で、最低ひとつは次を記録する。

- 新しく理解したドメイン知識
- 採用または却下した設計判断
- 使ったPHP/Laravelの言語・フレームワーク機能
- フロントエンドまたはデザイン上の原則
- AIに任せた作業と、人間が判断した作業
- 将来自作ライブラリとして切り出せそうな境界
